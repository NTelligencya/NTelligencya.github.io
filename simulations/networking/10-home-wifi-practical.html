WHAT YOU ARE DOING HERE

The task, in plain English

You are the technician setting up a small home wireless network for a client. The router has just arrived (it may have been used before), and there is a desktop PC, a wireless printer and a phone that all need to get onto the new network. Everything you would touch on a real bench is on this page: the packing list, the router and its sticker, the PC's ports, the printer's own setup screen, the router's web page, and the PC's Windows screens and Command Prompt.

Work in the order a technician would: check the box, reset the router, connect by cable, log in and lock it down, set up both Wi-Fi bands, get the PC onto Wi-Fi with a USB adapter, add the printer, then prove it all works from the Command Prompt. The checkpoint list on the left ticks itself only when the bench, the router and the PC really show that step is done. Hints are there if you get stuck; the last hint always gives the exact steps.

What the real task looks for. In the ICTSAS217 practical you are watched doing this sequence on real equipment, on two separate occasions. The observer wants to see that you can: reset a modem/router to factory settings; change its default administrator password; set the network name and security for both the 2.4 GHz and 5 GHz Wi-Fi; install a wireless network adapter in a PC and confirm it works; connect to the new network wirelessly with the credentials you set; set up a wireless network printer and print a test page; ping another device from the Command Prompt; show the PC's IPv4 address; and explain how to see which devices are connected to the network.

The unit behind it also expects the things around the bench: checking a delivery against its packing list, knowing what to do when something is missing, storing spare adapters properly, disposing of packaging and old equipment responsibly, and recording what you installed. Those are the first and last steps here. Completing the list here means you have rehearsed the sequence in a model; it is not an assessment and nothing is recorded anywhere but your own browser.

    What this bench models, and what it leaves out

    A generic dual-band home router with a web management page (status, wireless, administration, LAN, connected devices), DHCP leases in one /24, a PC with a wired port and a USB wireless adapter, a 2.4 GHz-only wireless printer with a fixed address, and a phone. The PC side shows the parts of Windows 11 the practical uses: the Wi-Fi list, Device Manager, Printers & scanners and a Command Prompt that understands ipconfig, ping, arp -a and netsh wlan. Every line of output is derived from the state of the bench; nothing is canned.

    Not modelled: real 802.11 radio behaviour (channels, interference, signal strength, range), the internet beyond a WAN light and one resolvable name, DNS in general, IPv6 beyond a link-local line, guest networks, MAC filtering, port forwarding, firmware updates, and any particular brand's interface. Some phones ignore ping; this one answers. Completing the checklist means you have rehearsed the sequence in a model, not that competence has been assessed.
